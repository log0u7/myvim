INTRODUCTION                                                    *myvim*

MyVim is a personal configuration plugin: it ships the settings, mappings
and per-plugin configuration of a DevOps IDE, while the plugins themselves
are managed by vim-plugin-manager as Git submodules of `~/.vim`.

STRUCTURE                                                *myvim-structure*

The `plugin/` directory follows a naming convention:

    vim_*.vim      Pure Vim configuration: options, mappings, colorscheme
    plugin_*.vim   Per-plugin configuration (g: variables, autocmds)

Files:
    vim_settings.vim        General options (undo, swap, diff, commands)
    vim_aliases.vim         Command aliases (`W` sudo-write, `Q` quit-all)
    vim_mappings.vim        Every global key mapping (single audit point)
    vim_colorscheme.vim     Colorscheme selection mechanism
    plugin_pluginmanager.vim  vim-plugin-manager: vimrc path, sidebar width
    plugin_coc.vim          coc.nvim LSP: extensions, generic servers, mappings
    plugin_vimai.vim        vim-ai AI assistant (local ollama endpoint)
    plugin_ale.vim          ALE linters for devops filetypes
    plugin_gutentags.vim    ctags exclusions
    plugin_<name>.vim       One file per configured plugin
    ftplugin/yaml.vim       Filetype-specific settings (2-space indent)

Essential settings that must run before plugins load (mapleader, encoding,
filetype, syntax) stay in `~/.vim/vimrc`.

COC.NVIM (LSP)                                          *myvim-coc*

YouCompleteMe was retired on 2026-09-16; coc.nvim provides generic LSP.
Extensions are declared in `plugin/plugin_coc.vim` via
`g:coc_global_extensions` (yaml, json, git, sh, docker, toml, ansible,
vimlsp) and auto-install at startup. Generic servers (terraform-ls) are
configured through `g:coc_user_config`. ALE stays in charge of the devops
linters with `ale_disable_lsp=1`.

LSP mappings: `gd` definition, `gr` references, `gi` implementation,
`K` hover, `[g`/`]g` diagnostic navigation, `<leader>rn` rename,
`<leader>ca` code action, `<leader>d` diagnostics, `<leader>o` outline.

NODE RUNTIME                                            *myvim-coc-node*

coc requires node >= 20 (RegExp `v` flag in its bundle): a distro node 18
crashes the client at startup. mise users pin coc to a managed node with
`g:coc_node_path` (already set in plugin_coc.vim to the mise node 22
install; bump the path after a node upgrade) while keeping the system
default untouched. Without the pin, coc uses `node` from PATH, so a node
>= 20 there works with no configuration.

AI ASSISTANT                                            *myvim-ai*

`plugin_vimai.vim` wires vim-ai to the LOCAL ollama server
(OpenAI-compatible endpoint), configured through `roles.ini` next to the
plugin. `:AI {prompt}` completes, `:AIChat` opens a conversation. Any
OpenAI-compatible provider works by editing `roles.ini`.

MAPPINGS                                                *myvim-mappings*

    <F2>            NERDTree toggle
    <F3>            Plugin Manager sidebar
    <F4>            Minimap toggle
    <F7>            Undotree toggle
    <F8>            Markdown Preview (markdown buffers)
    <C-p>           CtrlP files (plugin default)
    <leader>p       fzf Files
    <leader>b       fzf Buffers
    <leader>g       fzf Git files

Command mappings execute through `<Cmd>` (mode-independent, no jumplist
or search-history pollution). The `W` and `Q` command aliases are in
`vim_aliases.vim`.

EXTENDING                                                *myvim-extend*

Add a plugin: declare it in the `PluginBegin` block of `~/.vim/vimrc`, then
create `plugin/plugin_<name>.vim` for its `g:` variables and autocmds, and
add its key mappings to `vim_mappings.vim`. Filetype-specific settings go
to `ftplugin/<filetype>.vim`. Regenerate help tags with
`:PluginManager helptags` or `:helptags ALL`.
