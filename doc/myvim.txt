INTRODUCTION                                                    *myvim*

MyVim is a personal configuration plugin: it ships the settings, mappings
and per-plugin configuration of a DevOps IDE, while the plugins themselves
are managed by vim-plugin-manager as Git submodules of `~/.vim`.

STRUCTURE                                                *myvim-structure*

The `plugin/` directory follows a naming convention:

    vim_*.vim      Pure Vim configuration: options, mappings, colorscheme
    plugin_*.vim   Per-plugin configuration (g: variables, autocmds)

Files:
    vim_settings.vim        General options (undo, swap, diff; dirs auto-created)
    vim_aliases.vim         Command aliases (`W` -> eunuch `:SudoWrite`, `Q` quit-all)
    vim_mappings.vim        Every global key mapping (single audit point)
    vim_mouse_clip.vim      Mouse capture toggle (F6) + OSC52 clipboard over SSH
    vim_colorscheme.vim     Colorscheme selection mechanism
    plugin_pluginmanager.vim  vim-plugin-manager: vimrc path, sidebar width
    plugin_coc.vim          coc.nvim LSP: extensions, generic servers, mappings,
                            node runtime resolution (mise)
    plugin_minimap.vim      wfxr/minimap.vim options (code-minimap binary)
    plugin_vimai.vim        vim-ai AI assistant (local ollama endpoint)
    plugin_ale.vim          ALE linters for devops filetypes
    plugin_gutentags.vim    ctags exclusions
    plugin_<name>.vim       One file per configured plugin
    ftplugin/yaml.vim       Filetype-specific settings (2-space indent)

Essential settings that must run before plugins load (mapleader, encoding,
filetype, syntax) stay in `~/.vim/vimrc`.

COC.NVIM (LSP)                                          *myvim-coc*

YouCompleteMe was retired on 2026-09-16; coc.nvim provides generic LSP.
Extensions are declared in `plugin/plugin_coc.vim` via
`g:coc_global_extensions` (yaml, json, git, sh, docker, toml, ansible,
snippets, vimlsp) and auto-install at startup (coc-snippets bridges the
UltiSnips/vim-snippets snippets into the coc completion). Generic servers
(terraform-ls) are configured through `g:coc_user_config`. ALE stays in
charge of the devops linters with `ale_disable_lsp=1`.

LSP mappings: `gd` definition, `gr` references, `gi` implementation,
`K` hover, `[g`/`]g` diagnostic navigation, `<leader>rn` rename,
`<leader>ca` code action, `<leader>d` diagnostics, `<leader>o` outline.

NODE RUNTIME                                            *myvim-coc-node*

coc requires node >= 20 (RegExp `v` flag in its bundle): a distro node 18
crashes the client at startup. The authoritative fix is system-side:
make the PATH node >= 20 (`mise use -g node@22` with mise, or any node
>= 20 in PATH). coc spawns its service when ITS plugin loads, and
coc.nvim sorts before myvim (alphabetical pack order): a
`g:coc_node_path` set later cannot rescue the service spawn - it only
helps a manual `:CocStart`. `plugin_coc.vim` therefore keeps a mise
resolution + diagnostic warning as fallback (`[myvim] coc: no node >=
20 found ...`), and `$COC_NODE_PATH` (coc-native, read from the
environment) is the pin-free coc-only override. The vimrc stays
generic and minimal.

AI ASSISTANT                                            *myvim-ai*

`plugin_vimai.vim` wires vim-ai to the LOCAL ollama server
(OpenAI-compatible endpoint), configured through `roles.ini` next to the
plugin. `:AI {prompt}` completes, `:AIChat` opens a conversation. Any
OpenAI-compatible provider works by editing `roles.ini`.

MAPPINGS                                                *myvim-mappings*

    <F2>            NERDTree toggle
    <F3>            Plugin Manager sidebar
    <F4>            Minimap toggle (wfxr/minimap.vim; needs the
                    code-minimap binary: cargo install code-minimap)
    <F9>            Mouse capture toggle: vim (visual selection) ⇄
                    terminal (native selection = terminal copy/paste)
    <F7>            Undotree toggle
    <F8>            Markdown Preview (markdown buffers)
    <C-p>           fzf Files
    <leader>p       fzf Files
    <leader>b       fzf Buffers
    <leader>g       fzf Git files

vdebug (Xdebug) owns F2-F6/F10 inside a debug session (step over, step
into, step out, close, breakpoint): its buffer-local mappings win over
the global ones there. Between sessions, F4 stays the minimap.

Command mappings execute through `<Cmd>` (mode-independent, no jumplist
or search-history pollution). The `W` (delegates to the vim-eunuch
`:SudoWrite`) and `Q` command aliases are in `vim_aliases.vim`.

MOUSE AND CLIPBOARD                                      *myvim-mouse-clip*

`vim_mouse_clip.vim` holds two behaviors. The F9 toggle switches the
`mouse` option between `a` (vim handles the mouse: visual selection,
scrolling) and `""` (the terminal handles it: selecting copies in the
terminal, paste with the terminal binding). OSC52: on an SSH session
(`$SSH_CONNECTION` set), every yank also sends the yanked text to the
LOCAL clipboard through the OSC52 escape sequence, which travels
through ssh; no `+clipboard` build is needed. Local sessions stay
no-op (the terminal selection covers them), and yanks over ~100KB are
skipped.

EXTENDING                                                *myvim-extend*

Add a plugin: declare it in the `PluginBegin` block of `~/.vim/vimrc`, then
create `plugin/plugin_<name>.vim` for its `g:` variables and autocmds, and
add its key mappings to `vim_mappings.vim`. Filetype-specific settings go
to `ftplugin/<filetype>.vim`. Regenerate help tags with
`:PluginManager helptags` or `:helptags ALL`.
